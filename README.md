# Навчальний Пульс

Веб-версія застосунку Стрийського фахового коледжу ЛНУП: розклад, журнал, новини, контакти та реквізити оплати. Працює на телефоні, планшеті й комп'ютері, встановлюється на домашній екран як PWA. Хостинг — безкоштовний Cloudflare Workers.

**Розгорнута версія:** <https://edupulse-pwa.olehnana1236.workers.dev>

## Можливості

- **Розклад** — вибір групи або викладача, календар із доступними датами, кнопка «Сьогодні», пари з аудиторіями, позначка замін, підсвітка пари, яка триває зараз, і прогрес вивчення предметів.
- **Журнал** — оцінки, теми уроків, домашні завдання, самостійна робота та середній бал по предметах. Відкривається **без входу** — потрібні лише група, прізвище та ім'я.
- **Сповіщення про нові оцінки** — вмикається одним дотиком у вкладці «Журнал»: браузер надсилає push, коли в журналі з'явиться нова оцінка. Перевірка журналу — двічі на годину.
- **Новини** коледжу — з сайту на WordPress.
- **Контакти** адміністрації, навчальної частини, завідувачів і бухгалтерії.
- **Реквізити оплати** з автопідстановкою прізвища, імені та групи у призначенні платежу.
- **Темна й світла тема**, офлайн-кеш, встановлення на домашній екран.
- **Вхід через Google** (за бажанням) — потрібен акаунт `@sclnau.com.ua`. Без нього працює все, окрім кабінету.

## Як запустити локально

```bash
npm install
npx wrangler dev
```

Відкрити <http://127.0.0.1:8799>

Щоб працювали й сповіщення, скопіюйте `.dev.vars.example` у `.dev.vars` і впишіть туди `VAPID_PRIVATE_KEY` (ключ генерується командою `npm run vapid:gen`).

## Як задеплоїти

```bash
npx wrangler login
npx wrangler deploy
```

Wrangler покаже адресу виду `https://edupulse-pwa.<твій-нік>.workers.dev`.

Токен журналу лежить у відкритому коді — це нормально, він публічний за своєю природою (див. «Безпека» нижче). Якщо все ж захочете його сховати, задайте як секрет:

```bash
npx wrangler secret put JOURNAL_API_TOKEN
```

Тоді `env.JOURNAL_API_TOKEN` матиме пріоритет над значенням у `worker.js`.

## Сповіщення про нові оцінки

Web push працює «на себе»: ключі VAPID наші власні, push-сервіс стандартний (Chrome/Firefox надсилають до нього згенеровані ними ключі), а журнал перевіряє власний воркер за розкладом.

1. **Простір KV** для підписок (уже створений і прописаний у `wrangler.toml`):

   ```bash
   npx wrangler kv namespace create PUSH_SUBS
   ```

   Після створення вставте отриманий `id` у секцію `[[kv_namespaces]]` файлу `wrangler.toml`.

2. **Ключі VAPID** — згенерувати пару:

   ```bash
   npm run vapid:gen
   ```

   Публічний ключ (`BD9WRsrp…`) лежить у `worker.js` і роздається браузерам, це нормально. Приватний — у секрет воркера:

   ```bash
   npx wrangler secret put VAPID_PRIVATE_KEY
   ```

   Для локального запуску покладіть його ж у `.dev.vars` (див. `.dev.vars.example`).

3. **Хронологія** — `crons = ["23,53 * * * *"]` у `wrangler.toml`, тобто перевірка журналу двічі на годину. На безкоштовному плані Cloudflare хронологія не гарантує точну хвилину.

Як це влаштовано:

- браузер надсилає `POST /api/push/subscribe` з підпискою (endpoint + ключі `p256dh`/`auth`) і групою та ПІБ;
- воркер зберігає підписку й **знімок** оцінок у KV, а в `/api/push/key` віддає публічний ключ VAPID;
- щоразу за хронологією воркер тягне журнал, порівнює зі знімком і надсилає push лише тим, у кого з'явилась нова оцінка;
- сам push шифрується за RFC 8291 (`aes128gcm`) і підписується за RFC 8292 (VAPID), ключі ніколи не залишають воркер у відкритому вигляді.

Запис у KV робиться лише тоді, коли знімок справді змінився — добова квота записів (1000 на безкоштовному тарифі) не витрачається на порожні перевірки. Якщо сервер журналу раптом віддає обрізану відповідь, такий цикл ігнорується, щоб не прийшли фальшиві сповіщення.

Перевірити локально:

```bash
npm test            # шифрування за тест-вектором RFC 8291
npm run test:e2e    # наскрізна перевірка: підписка → хронологія → push → розшифрування
```

## Як це працює

```
Браузер ──► Cloudflare Worker (ваш origin)
                ├──► tt.sclnau.com.ua      розклад, групи, контакти, реквізити (публічні)
                ├──► journal-api.sclnau.com.ua  журнал (ключ у заголовку X-Auth-Token)
                ├──► tt-api.sclnau.com.ua     кабінет (Bearer-токен користувача)
                └──► sclnau.com.ua/wp-json     новини (WordPress REST)

Хронологія (раз на 30 хв) ──► журнал ──► порівняння зі знімком ──► push-сервіс (FCM/Mozilla)
```

- Google Identity Services у браузері віддає Google ID-token.
- `POST /api/auth` обмінює його на Firebase-сесію (`identitytoolkit.googleapis.com`) і перевіряє, що пошта має домен коледжу.
- `GET /api/me` та інші `/api/*` кабінету надсилають `Authorization: Bearer <firebase-id-token>`.
- Токен автоматично оновлюється через `POST /api/refresh`.

## Безпека

- Відповіді з авторизацією не кешуються ні в service worker, ні в браузері (`Cache-Control: private, no-store`).
- `POST /api/auth` і `POST /api/refresh` перевіряють `Origin` запиту — запити з чужих доменів відхиляються.
- `POST /api/push/subscribe` і `POST /api/push/unsubscribe` так само перевіряють `Origin`.
- Приватний ключ VAPID лежить у секреті воркера (`wrangler secret`), а не в репозиторії; публічний ключ роздається браузерам — це задумано.
- Ключ Journal API (`X-Auth-Token`) лежить у відкритому коді — і це не витік. Це публічний ключ: той самий, що вбудований у мобільний застосунок коледжу, доступний кожному, хто його встановив. Дані журналу і так відкриті для всіх, хто знає групу та ПІБ студента. Якщо захочете прибрати ключ із репозиторію — скористайтеся `JOURNAL_API_TOKEN` (див. вище).

## Відомі обмеження

- **Сповіщення на iPhone** працюють лише у встановленому застосунку (PWA), а не у вкладці Safari: додайте сайт на головний екран і відкривайте звідти.
- Push-сповіщення приходять не миттєво: журнал перевіряється двічі на годину.
- Кнопка Google на iOS у режимі PWA відкривається як popup; якщо його блокує браузер — додайте сайт на головний екран через Safari.
- Список доступних дат береться з сервера коледжу, тому в кеші він живе до 15 хвилин.

## Файли

| Файл | Призначення |
|---|---|
| `worker.js` | API-проксі, автентифікація, роздача статики, версійний хеш, хронологія сповіщень |
| `webpush.mjs` | шифрування push (RFC 8291) та підпис VAPID (RFC 8292) |
| `index.html` | каркас застосунку |
| `styles.css` | теми та компоненти |
| `app.js` | логіка екранів: розклад, журнал, новини, контакти, оплата, вхід, сповіщення |
| `sw.js` | service worker: офлайн-кеш і показ сповіщень |
| `manifest.webmanifest` | маніфест для встановлення PWA |
| `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` | іконки застосунку |
| `scripts/gen-vapid-keys.mjs` | генератор пари ключів VAPID |
| `test/webpush.test.mjs` | тест-вектор RFC 8291 (побайтове порівняння) |
| `test/push.e2e.mjs` | наскрізна перевірка сповіщень на локальному воркері |

Версія для кешування рахується як хеш вмісту файлів і підставляється в `index.html` та `sw.js` під час деплою, тому браузер оновлює застосунок сам, без ручного `?v=N`.
